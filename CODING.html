Algorithms and coding

How to code in an interview

  1. Restate the problem in one sentence, and ask about input size, empty input, duplicates and negative numbers.
  2. Say the brute force and its cost before anything clever. It's a correct answer you can improve.
  3. Name the pattern ("this is a sliding window") and the better complexity.
  4. Write it while talking. Clear names over short ones. Syntax matters less than structure.
  5. Run one small example by hand, then the edge cases: empty, one element, all the same.
  6. State time and space at the end, and one way you'd improve it if they asked.
